\begin{abstract}
Complexity measured from generated code is failure-dependent: a difficult prompt can produce a short failing program and then be assigned low output complexity. We introduce a six-dimension prompt-side structural-complexity index that is scored before generation and kept separate from functional correctness. We first select 5{,}000 Python prompts across six bands of a preliminary single-rater rubric score. Four out-of-panel LLM raters then rescore the locked prompts, providing 19{,}997 score rows; composite inter-rater reliability is ICC $=0.872$ on the 4{,}998 prompts with all four ratings. We evaluate 21 models on every prompt, yielding 105{,}000 model-prompt generations, and an independent LLM auditor, validated on known-answer cases, reviews every unit-test verdict. In the unadjusted mean-pooled analysis, pass rate has a nonmonotone breakpoint at composite $\hat{\gamma}=14.0$, with 83.4\% at or below and 90.1\% above. This pooled pattern is not a universal failure cutoff. Task-type fixed effects shift the breakpoint to 11.5 and reduce the regime gap from 6.8 to 2.1 percentage points, and neither construction frame alone reproduces the pooled change: the later frame breaks at 14.25 with a 1.8-point change, and the earlier frame shows no significant break. In the unadjusted model-specific fits, 19 models have higher raw mean pass above their selected breakpoint and two have lower. Kimi K2.5 is the clearest benchmark-conditional downward example: construction-frame-controlled and separate later-frame searches both select $\hat{\gamma}=14.25$, with later-frame raw mean pass of 0.848 at or below and 0.808 above and a 95\% pairs-bootstrap interval of $[14.00,14.75]$. A 365-prompt audit-clean extension closely matches the original matched-five-model estimates at the well-supported bins 15 and 16, but adds only 14 prompts above bin 16. Among zero-pass generations with computable Lizard complexity, 25.0\% pair a prompt composite above 8 with generated-output complexity at most 10, illustrating the measurement problem. The pooled breakpoint is 11.25 on raw unit-test outcomes and 13.75 under the reviewed version's partial audit, with one and five downward models. Human agreement is moderate and rater-dependent on a disagreement-enriched calibration set, while paraphrase and cross-language rescoring preserve score ordering. Overidentification tests strongly reject the joint restrictions on the six rubric dimensions, so we treat the composite as an index and make no causal interpretation of the 2SLS estimates. The contribution is a pre-generation framework for estimating model-specific, benchmark-conditional reliability breakpoints and auditing their sensitivity to prompt composition and outcome definition.
\end{abstract}

\section{Introduction}
% =====================================================================

Code-generating LLMs are evaluated functionally: does the generated program pass the tests~\cite{chen2021evaluating,austin2021program,jimenez2023swebench}? That question does not directly answer how reliability varies with the structure a task requires; two models with similar average pass rates may behave very differently on prompts that demand interacting branches, data structures, edge cases, or algorithmic steps.

The difficulty is that task complexity is often measured after generation, from the program the model produced. When a model fails, the output is often a short stub, partial solution, or broken program with low measured cyclomatic complexity, so a structurally demanding prompt can enter a low-complexity bin precisely because the model failed. This failure-dependent measurement can flatten, shift, or hide the relationship between task structure and pass rate. We call this the \emph{Reverse Threshold Problem}: the apparent unreliability of simple generated code may partly reflect more complex code that was never produced. Keyword counts over the instruction avoid the timing problem but reduce interacting structure to surface cues; we instead use a rubric that asks separate questions about branching, iteration, state, data structures, edge cases, and composition. It is still a proxy, but it is measured at the right time: before the evaluated model answers.

We present the Complexity Kink benchmark, which keeps intended solution structure separate from generated-output complexity and functional correctness. From OpenCodeInstruct~\cite{opencodeinst} we construct 5{,}000 Python prompts stratified on a preliminary single-rater rubric score; four out-of-panel LLM judges rescore the locked prompts, 21 models each generate one solution per prompt, and an independent auditor reviews every unit-test verdict. We estimate model-specific and pooled reliability breakpoints on the unbinned ensemble index, each conditional on the model or pooling rule, prompt frame, scoring index, generation settings, and test protocol. We also report output-side complexity comparisons and 2SLS diagnostics, but the candidate instruments fail their joint exclusion restrictions and receive no causal interpretation.

The empirical results do not support a universal cutoff. The mean-pooled curve declines through the middle of the index and rebounds in the denser high region, but task type and construction frame account for much of the gap. In particular, the two prompt-source frames differ sharply in both score and pass rate, and neither reproduces the pooled $+6.8$-point change on its own. In the unadjusted original benchmark, two model-specific fits have lower raw mean pass above their selected split and 19 have higher raw mean pass; these are descriptive regime contrasts, not construction-frame-stable failure onsets. Kimi K2.5 provides the clearest downward example after construction-frame control and separate analysis of the later frame. A matched five-model extension closely matches the original estimates at bins 15 and 16, where it materially increases support, but the region above 16 remains too thin for a strong endpoint claim.

\vspace{2pt}
\noindent\textbf{Contributions.}
\begin{itemize}
\item We formalize failure-dependent output complexity and illustrate it in this sample: 25.0\% of zero-pass complete cases combine a structurally nontrivial prompt with generated-output cyclomatic complexity at most 10.
\item We introduce an ensemble-scored prompt-side index and examine its reliability against human ratings, plain-language paraphrases, and Java and C++ re-expressions.
\item We construct and publicly release a 5{,}000-prompt Python benchmark with all judge scores, 105{,}000 generations, and test outcomes,\footnote{Code and data: \codeurl{}.} and use it to estimate model-specific reliability breakpoints conditional on the scoring index, prompt frame, generation settings, and unit-test protocol.
\item We audit those estimates under pooling, repeated sampling, task type, construction frame, outcome definition, and an audit-clean tail extension, and report when an apparent breakpoint is composition-sensitive.
\end{itemize}

\section{Related Work}
% =====================================================================

\textbf{LLM code evaluation.} HumanEval~\cite{chen2021evaluating}, MBPP~\cite{austin2021program}, and SWE-Bench~\cite{jimenez2023swebench} established functional testing as the central protocol for code-generating LLMs; that functional outcome remains our target variable. We instead study how to measure the structure of the task being attempted. OpenCodeInstruct~\cite{opencodeinst} supplies instruction-code pairs, but reference code reflects one implementation rather than latent task structure.

\textbf{Complexity measurement and benchmark bias.} Cyclomatic complexity is computable from source code, from McCabe's formulation to static analyzers such as Lizard~\cite{mccabe1976complexity,lizard}. In code-generation evaluation the available source is often the model output, which makes the metric post-treatment: measured complexity depends on success or failure~\cite{montgomery2018posttreatment}. We score the prompt before generation instead.

\textbf{Instrumental variables and threshold estimation.} IVs are a standard response to endogenous regressors~\cite{wooldridge2010econometric}, with weak-instrument and overidentification tests as essential diagnostics~\cite{stock2005testing,hansen1982large,bowsher2002reject}, and are increasingly used in empirical software engineering~\cite{grafvlachy2024cleaning,siebert2023applications}. Our rubric-dimension IV fits fail these diagnostics and are retained only as such; the primary analysis adapts Hansen's threshold regression and bootstrap sup-Wald test~\cite{hansen2000sample} to the composite directly.

\textbf{LLMs as judges.} G-Eval~\cite{liu2023geval}, AlpacaEval~\cite{alpacaeval}, and MT-Bench~\cite{zheng2023judging} use LLMs to evaluate model outputs, building on rubric-based automatic evaluation in NLP~\cite{hashimoto2019unifying}. Our rubric judges score the input prompt before generation against a published structural rubric and are excluded from the evaluated panel, making them a measurement layer for a latent input property rather than an outcome evaluator. A separate LLM auditor reviews unit-test verdicts (Section~\ref{sec:data}).

\section{Background: Failure-Dependent Output Complexity}
% =====================================================================

Let $\kappa_i^*$ denote the latent structure required by task $i$, let $y_{im}$ denote the functional outcome for model $m$, and let $\kappa_{im}^{\mathrm{obs}}$ be the cyclomatic complexity measured on that model's generated output. Even a passing output is only one implementation of the task, so $\kappa_{im}^{\mathrm{obs}}$ need not equal $\kappa_i^*$. More importantly, the measurement itself depends on the outcome:
\begin{equation}
\kappa_{im}^{\mathrm{obs}} = g(\kappa_i^*, y_{im}, \eta_{im}),
\label{eq:failure-dependent}
\end{equation}
where failed generations often collapse to short programs with low measured complexity. Stratifying pass rate by $\kappa_{im}^{\mathrm{obs}}$ therefore conditions on a post-generation quantity affected by success.

We address the timing problem with a prompt-side index $C_i$, computed before any evaluated model generates code. Our primary target is descriptive: the conditional relationship $\mathbb{E}[y_i\mid C_i]$ in the constructed benchmark, where $y_i$ is pass rate averaged over evaluated models. The six rubric dimensions can also be considered as candidate instruments for $\kappa_i^{\mathrm{obs}}$, but causal interpretation would require strong exclusion restrictions. The diagnostics below reject those restrictions, so the IV analysis does not identify a causal effect.

\section{Methodology}
% =====================================================================

\subsection{Data}\label{sec:data}
We use 5{,}000 Python tasks from OpenCodeInstruct~\cite{opencodeinst}: 2{,}246 prompts retained from an earlier stage, drawn from a 200{,}000-record source-ordered prefix, plus 2{,}754 later candidates that passed automated contract and test-quality filtering and deliberately supplemented the high reference-complexity tail. We retain this two-level construction-frame indicator for post hoc sensitivity analysis. A preliminary \texttt{o4-mini} rater scored candidates with the rubric below, and we sampled 834 prompts in each of the preliminary-score bands 0--3 and 4--6 and 833 in each of 7--9, 10--12, 13--15, and 16--24. This score was used for sampling only.

After the prompt set was locked, the four-judge ensemble rescored every prompt, and all analyses use that ensemble mean. On the bands $[0,3]$, $(3,6]$, $(6,9]$, $(9,12]$, $(12,15]$, $(15,24]$ the analyzed index has 319, 943, 940, 898, 1{,}425, and 475 prompts, so the benchmark is stratified by the preliminary score but not balanced on the final index; neither matches the natural OpenCodeInstruct distribution. Reference-solution cyclomatic complexity shaped the upstream pool and is used only for alignment checks.

The evaluated panel has 21 models: Claude Opus 4.6, Opus 4.7, and Sonnet 4.6; GPT-5.4, GPT-5-mini, GPT-4.1, GPT-OSS-20B, and GPT-OSS-120B; Gemini 3.1 Pro Preview and Gemini 3 Flash; Grok-3; DeepSeek V3.2; Kimi K2.5; Qwen 3.6 Plus and Qwen 3.5-9B; Mistral Large-3, Devstral Small 2505 (4-bit quantized), and Ministral-3-14B-reasoning; Llama 3.3-70B; GLM 4.7-flash; and Trinity-large. No rubric judge is in the panel. A locally served, quantized AuroraGPT-IT-v4 run covered only the earlier frame and was excluded in a post hoc decision without a prespecified eligibility rule; its earlier-frame pass rate was 20.6\%, and performance was not a documented exclusion criterion. Each model generated one solution per prompt ($21\times5{,}000=105{,}000$ generations). Pass rate starts from the fraction of Nvidia-supplied unit tests passed. Because tests can reject valid code (e.g., a renamed function) or miss defects, MiMo-V2.6-Pro, an auditor from a vendor used nowhere else in the study, reviewed every generation's task, code, tests, and harness result: ``correct'' sets pass rate to 1.0, ``incorrect'' to 0.0, and uncertain or unparseable verdicts (1.1\%) keep the harness value, raising mean pass from 0.792 to 0.851. Appendix~\ref{app:outcome-audit} gives its known-answer validation, departures from the selection protocol, and second-auditor agreement, and repeats the main analyses on raw harness outcomes and under the reviewed version's partial \texttt{o4-mini} audit. The combined analysis averages pass rate across the 21 models within prompt ($N=5{,}000$), and per-model analyses use the same 5{,}000 rows. Generated-output complexity is McCabe cyclomatic complexity from Lizard~\cite{lizard}, summed over the functions in the cleaned generated code; it is available for 103{,}948 generations, and analyses using it report complete-case denominators.

\subsection{Rubric Scoring}

Four out-of-panel LLM judges deployed through Azure AI Foundry, \texttt{o4-mini}, \texttt{gpt-5.5}, \texttt{llama-4-maverick}, and \texttt{command-a}, score every prompt with the same rubric prompt: 4{,}998 prompts have four scores, one has three, and one has two (19{,}997 score rows). We average each prompt-dimension pair across available judges; composite ICC is 0.872 on the 4{,}998 complete cases, and scorer disagreement is retained for diagnostics. Each prompt is scored on six dimensions, each $0$ to $4$ (Table~\ref{tab:complexity_dimensions}).

The primary prompt-side index is $C_i = \sum_{d=1}^{6} Z_{i,d} \in [0,24]$, where $Z_{i,d}$ is the ensemble mean for dimension $d$. The dimension vector $\mathbf{Z}_i=(Z_{i,1},\ldots,Z_{i,6})$ is retained for interpretation, reliability analysis, and secondary IV diagnostics.

\textbf{Design decisions.} Separate dimensions make the index interpretable, expose where raters disagree, allow per-dimension human calibration, and permit an overidentification test when treated as candidate IVs. The five-point scale admits a neutral middle score for ambiguous prompts. Each dimension is anchored to expected solution structure and explicitly excludes LLM difficulty, code length, and language idioms, so the outcome is not built into the measure. Excluding the judges from the evaluated panel reduces circularity but does not by itself establish accuracy, human agreement, or IV exclusion.

\subsection{Primary Breakpoint Analysis}
For a candidate breakpoint $\gamma$, we fit separate linear relationships on the two sides of the prompt-side composite:
\begin{equation}
\mathbb{E}[y_i\mid C_i] =
\begin{cases}
\alpha_1+\beta_1 C_i, & C_i\leq\gamma,\\
\alpha_2+\beta_2 C_i, & C_i>\gamma.
\end{cases}
\label{eq:threshold}
\end{equation}
The mean-pooled outcome averages pass rate across the 21 models within prompt ($N=5{,}000$); model-specific fits use the same index and test harness, and we also report median pooling and 21 leave-one-model-out fits. Regime means are descriptive summaries of a selection-stratified sample. A model-specific $\hat{\gamma}$ estimates where the conditional pass-rate relationship changes for one named model under this benchmark and protocol; it does not by itself identify a causal, universal, or deployment-level failure threshold, and direction is read from the raw regime means rather than from breakpoint significance. Because construction combines two prompt-source frames, we also add a frame indicator to the pooled and split regressions (for the mean-pooled fit and, post hoc, for the models with downward unadjusted contrasts), compare frame-specific linear slopes, and repeat the search within each frame.

To locate the breakpoint, we adapt Hansen's threshold-regression procedure~\cite{hansen2000sample}:
\begin{enumerate}
\item For each candidate $\gamma$ on a percentile-spaced grid over $C_i$, requiring at least 500 prompts in each regime, we compare (\ref{eq:threshold}) with a pooled single-line model using a Wald-type $F$-statistic $W(\gamma)$.
\item The supremum $W^* = \sup_\gamma W(\gamma)$ identifies the threshold $\hat{\gamma}$.
\item Under $H_0$ of no threshold, we use Rademacher wild-bootstrap residual resampling and recompute $W^*$ at each draw. A separate pairs bootstrap estimates the threshold interval.
\end{enumerate}
We repeat the pooled search with nine task-type fixed effects and, separately, with the construction-frame indicator. Bootstrap and placebo draw counts for every specification are listed in Appendix~\ref{app:robustness}.

\subsection{Output-Complexity and IV Diagnostics}\label{sec:hansen-j}
We first compare pass rate directly against generated-output complexity and quantify the reverse-threshold cell among failed generations. As a secondary diagnostic, we regress generated-output complexity on the six rubric dimensions and use the fitted value in a 2SLS pass-rate regression:
\begin{align}
\kappa_i^{\mathrm{obs}} &= \pi_0+\mathbf{Z}_i\boldsymbol{\pi}+\nu_i, \label{eq:stage1}\\
y_i &= \alpha+\beta\widehat{\kappa}_i+u_i. \label{eq:stage2}
\end{align}
We estimate these with \texttt{IV2SLS} from \texttt{linearmodels}~\cite{linearmodels} and report Sargan (five degrees of freedom) and robust Wooldridge overidentification tests, individual-instrument fits, principal-component rotations, and post hoc subsets. These tests reject the full instrument set, so $\hat{\beta}$ is a diagnostic coefficient rather than a causal estimate.

\subsection{Additional Robustness Designs}
After the initial analysis we added post hoc stress tests, none preregistered: a nine-category task taxonomy, the construction-frame sensitivity above, a five-draw repeated-sampling subset, plain-language paraphrase and Java/C++ re-expression rescoring, a blind two-grader human calibration, and a 365-prompt audit-clean high-complexity extension. Designs are detailed in Appendix~\ref{app:robustness-designs}, and Figure~\ref{fig:pipeline} there summarizes the full workflow.

\section{Results}
% =====================================================================

\subsection{Alignment with Reference Complexity}

Because reference-solution cyclomatic complexity helped shape the candidate pool, alignment with it is an association check rather than independent validation. On the 4{,}997 prompts with a reference value, the composite has Pearson $r=0.80$ and Spearman $\rho=0.81$ with reference $\kappa$, rising from 4.64 at $\kappa=1$ to 14.33 at $\kappa\in[21,45]$, though not monotonically at every adjacent bin (Appendix Table~\ref{tab:rubric-ref-cc}). At the low end, where failed stubs make output CC collapse toward 1, the rubric separates $\kappa=1$ from $\kappa=2$ prompts ($+0.61$, $p=3.1\times10^{-4}$), driven by iteration, state, and branching. A lexical keyword baseline also separates them ($+0.58$, $p=2.4\times10^{-3}$; Appendix Table~\ref{tab:low-end-separation}), so the rubric does not dominate every cheap proxy; its advantages are explicit structural dimensions, measurable rater uncertainty, and the calibration checks below.

\subsection{Rater and Measurement Calibration}

Beyond the four-judge ICC of 0.872, we ran a deliberately difficult human calibration with LLM scores hidden: the first author graded 200 prompts, roughly half sampled for high judge disagreement, and the second author graded 50 of them. On all 200, first-author agreement with the ensemble is Pearson $r=0.408$, Spearman $\rho=0.373$, ICC$(2,1)=0.395$, with mean offset $-1.18$ points; per-dimension Pearson correlations range from 0.249 to 0.484 and quadratic-weighted $\kappa$ from 0.217 to 0.435. On the shared 50, the graders correlate 0.561 with each other and 0.613 and 0.921 with the ensemble, with offsets $-0.69$ and $-1.35$. These are stress-test estimates with substantial rater variation, not a human ground-truth certificate.

Two checks probe whether the index follows presentation rather than structure. Across 150 plain-language rewrites, rank stability is high (Spearman $\rho=0.963$); the mean shift is small ($-0.115$) but detectable (paired $p=0.031$), and 91.3\% of pairs are within one point. The rewrites were not verified by execution, so this is score stability under a preservation instruction, not proof of semantic equivalence. For 117 prompts re-expressed in Java and C++, the composite correlates 0.992 and 0.969 with Python, with inter-judge ICC 0.912 (Python), 0.913 (Java), and 0.882 (C++): evidence of score transfer, not of non-Python generation reliability.

\subsection{Generated-Output Complexity Misses the Prompt-Side Pattern}

Figure~\ref{fig:output-cc} compares reliability against Lizard complexity measured on the generated output: the curve is nonmonotone and shows no clean decline. Among 14{,}248 zero-pass generations with a computable Lizard value, 3{,}562 (25.0\%) have prompt composite $>8$ but output CC $\leq10$; the shares are 25.1\%, 25.2\%, and 25.4\% for pass rate at most 0.25, 0.50, and 0.65. In an automated evaluation pipeline with no human in the loop, these structurally demanding prompts would be silently binned as simple tasks. A further 968 zero-pass rows have no computable output CC and are excluded from these denominators.

Among passing generations only, where output CC is less contaminated by failed stubs, a descriptive linear mapping has $R^2=0.614$ and maps prompt $\hat{\gamma}=14.0$ to output CC about 23.6. This is a selection-conditioned scale translation, not a second threshold estimate. The OLS and 2SLS comparisons are reported in Appendix~\ref{app:econ-diagnostics}.

\subsection{The Mean-Pooled Breakpoint}

On the unadjusted mean-pooled benchmark, the sup-Wald search selects $\hat{\gamma}=14.0$ on the prompt composite, with sup-Wald $=151.10$. None of 2{,}000 wild-bootstrap draws or 2{,}000 shuffled-index placebo draws reaches the observed statistic; with the finite Monte Carlo correction, each gives $p_{\mathrm{MC}}\leq1/2001<0.001$. At or below $\hat{\gamma}$, $n=3{,}703$ prompts have mean pass rate 83.4\%; above it, $n=1{,}297$ have mean pass rate 90.1\%. The relationship is not a monotone collapse: pass rate declines through the middle of the index, reaches a trough near composite 10, and rebounds in the denser high region. A model comparison selects the piecewise form over linear and cubic specifications by BIC ($-69$ versus 208 and 32).

The 95\% pairs-bootstrap interval is $[10.5,14.25]$, spanning the region between the trough and the rebound in Figure~\ref{fig:kink}. The estimate summarizes an observational breakpoint in this constructed benchmark, not a universal point at which harder prompts become easier.

\subsection{Task-Type and Construction-Frame Sensitivity}\label{sec:frame}

We label all 5{,}000 prompts using a nine-category taxonomy fixed before labeling. One out-of-panel judge labels the full set; three more label a shared 500-prompt subset, with Krippendorff $\alpha=0.787$. Adding task-type fixed effects shifts $\hat{\gamma}$ from 14.0 to 11.5, reduces sup-Wald from 151.1 to 26.9, and reduces the raw regime gap from 6.8 to 2.1 percentage points. None of 300 wild-bootstrap draws reaches the observed controlled statistic ($p_{\mathrm{MC}}\leq1/301<0.01$). Task composition therefore explains a substantial part of the pooled pattern.

A piecewise composite term at 11.5 raises predictive $R^2$ from 0.093 for task type alone to 0.160; the piecewise term alone has $R^2=0.045$. This is incremental predictive fit, not causal independence. Four of five sufficiently large task categories still reject the full IV restrictions, so task type does not explain away the overidentification failure.

The construction-frame sensitivity is more consequential. The 2{,}246 retained earlier-frame prompts have mean composite 7.92 and mean pass rate 0.795, while the 2{,}754 later candidates have mean composite 11.42 and mean pass rate 0.897. A common construction-frame fixed effect leaves the breakpoint near the pooled value (14.25; sup-Wald 59.0, none of 300 wild-bootstrap draws exceeds it), and this breakpoint model has lower BIC than frame-specific linear slopes ($-247$ versus $-209$), so nonlinearity survives the control, although its raw regime means still mix the two frames.

The within-frame fits explain why we narrow the claim. The earlier frame selects 9.50, but the break is not significant (sup-Wald 4.01, bootstrap $p=0.14$), and a linear decline has lower BIC. The later candidate frame selects 14.25 and supports nonlinearity (sup-Wald 93.70, $p_{\mathrm{MC}}\leq1/301$), but its raw regime change is only $+1.8$ points (0.890 to 0.908). At the pooled threshold, later candidates make up 41.0\% of prompts at or below but 95.4\% above. Thus the pooled trough and rebound remain features of the constructed benchmark, while the large upward regime gap is largely construction-frame composition rather than evidence that increasing prompt complexity improves reliability.

\subsection{Model and Pooling Heterogeneity}

Model-specific thresholds in the unadjusted original benchmark range from 10.0 to 14.25, with median 10.75. Nineteen models have higher raw mean pass above their selected breakpoint and two have lower raw mean pass: Kimi K2.5 (0.817 to 0.801 at 14.0) and Gemini 3.1 Pro Preview (0.872 to 0.793 at 10.75). That count depends on the outcome definition: five models are downward under the reviewed version's partial audit and one on raw harness outcomes (Appendix~\ref{app:outcome-audit}).

Kimi K2.5 is the clearest downward case. Its construction-frame-controlled search selects $\hat{\gamma}=14.25$ with sup-Wald 32.03 and zero exceedances in 300 wild-bootstrap draws ($p_{\mathrm{MC}}\leq1/301$). Within the later candidate frame, it separately selects 14.25 with sup-Wald 41.62, a 95\% pairs-bootstrap interval of $[14.00,14.75]$, and raw mean pass of 0.848 at or below versus 0.808 above. Piecewise BIC is 2{,}284 versus 2{,}350 for a linear fit. The earlier Kimi frame has no significant breakpoint ($p_{\mathrm{MC}}=0.226$), and linear BIC is lower. Both 14.25 selections also hold on raw harness outcomes and under the reviewed version's audit. Gemini 3.1 Pro Preview's downward later-frame contrast at 14.75 (0.857 to 0.768) is poorly localized (interval $[8.00,14.75]$; linear BIC lower).

The same prompt set, scores, and test harness are reused, so these are comparative model fits rather than independent replications. The mean-pooled threshold remains exactly 14.0 in all 21 leave-one-model-out fits. Median pooling selects 10.5 and narrows the raw gap to 2.9 points (0.879 to 0.908). Full results appear in Appendix~\ref{app:per-model}; a library-mention diagnostic on a separate sample is in Appendix~\ref{app:library}.

We independently selected high-composite candidates on the prompt side, audited their contracts, and retained only prompts whose reference solution passes every supplied test. This yields 365 new prompts: 218/133/11/3 at display bins 15/16/17/18. The extension's generated code was not saved and cannot be audited, so this comparison uses raw harness outcomes on both sides. To avoid changing model composition, Figure~\ref{fig:tail-extension} uses the five models present in both the original and extension runs. At bin 15, the extension and original means are 0.880 and 0.890; at bin 16 they are 0.799 and 0.795. The differences are $-0.009$ and $+0.004$ (Welch $p=0.554$ and $p=0.906$). \subsection{Repeated-Sampling Robustness}

On a 359-prompt, four-model subset with five draws per prompt-model cell at temperature 0.8 (7{,}180 generations, raw harness outcomes), the mean within-cell standard deviation is 0.064 and the median is zero. The first draw and five-draw mean both select $\hat{\gamma}=14.25$. Their Pearson correlation is 0.960, but this is a part-whole comparison because the first draw contributes to the mean. This local check supports threshold-location stability for the sampled subset; it does not establish universal single-draw reliability.

% =====================================================================
\section{Discussion}
% =====================================================================

\textbf{The IV diagnostics.} The six-dimension IV specification does not support causal identification. Sargan $J=551.97$ on five degrees of freedom and the robust Wooldridge statistic (408.33) reject at machine precision, and not because of sample size: mean $J$ is already 33.3 at $n=250$ (null expectation about five), where every random subsample rejects. Just-identified coefficients conflict in sign (data structures $+0.00220$; state $-0.00402$; composition $-0.00452$), principal-component rotations do not repair the disagreement, and the few non-rejecting post hoc subsets are multiplicity-sensitive (Appendix~\ref{app:econ-diagnostics}). What survives is the composite as a pre-generation index: its timing avoids the failure dependence of output CC, and its agreement with reference CC, human ratings, paraphrases, and re-expressions can be checked directly. None of those checks makes it a causal instrument.

\textbf{What the breakpoint means.} The unadjusted mean-pooled breakpoint compactly describes a nonmonotone curve in a selection-stratified benchmark; it is not a universal difficulty limit. Task-type controls shrink its gap from 6.8 to 2.1 points, neither construction frame alone reproduces the pooled increase, median pooling moves it to 10.5, the outcome definition moves it between 11.25 and 14.0, and model-specific directions and their frame sensitivities differ. Leave-one-model-out stability shows that no single model drives the pooled estimate, but not independence from the pooling rule, prompt composition, or outcome definition. Kimi K2.5 is the clearest downward, benchmark-conditional example: its later-frame breakpoint and decline hold under all three outcome definitions. Gemini's downward later-frame change is poorly localized. A model-specific $\hat{\gamma}$ is therefore a candidate reliability breakpoint for a named model under this frame, index, generation setting, and test protocol. The 365-prompt extension adds evidence only where it adds support: rates closely match at bins 15 and 16, and the tail beyond them remains unresolved.

\textbf{Why a prompt-side index, and implications.} The central design choice is temporal: measure the input before the evaluated system acts. A lexical proxy shares that advantage and may be preferable when transparency or cost dominates; the rubric trades cost for interpretable structural dimensions and measurable rater disagreement, and the two-grader calibration argues for reporting that uncertainty rather than trusting any single rater. The principle may transfer beyond Python, but the evidence here covers only score transfer to Java and C++. Analyses that stratify by output complexity should report how failed and missing outputs enter the metric; prompt-side scores can supplement them when the sampling frame, rater reliability, bin support, alternative pooling, and task-adjusted results are shown. Such scores are diagnostic summaries, not deployment rules without prospective validation.

% =====================================================================
\section{Limitations}
\label{sec:limitations}
% =====================================================================
% \subsection{Current limitations}

\textbf{Constructed sampling frame.} The benchmark is balanced on a preliminary single-rater score, not the final index, and inherits a 200{,}000-record prefix scan and deliberate high-reference-complexity supplementation. The two construction frames differ sharply in score and pass rate, and their changing mixture explains much of the pooled rebound. The benchmark does not estimate performance under the natural OpenCodeInstruct distribution, and all estimates are conditional on the model or pooling rule, frame, index, generation settings, and test protocol.

\textbf{Composition and pooling.} Task-type controls and within-frame analysis substantially alter the breakpoint or its gap, and median pooling moves it; the mean-pooled 14.0 should not be read without those sensitivities.

\textbf{Outcome definition.} The outcome depends on one LLM auditor, adopted by author decision after no candidate met our pre-declared rule in full; it fell three cases short on clean accuracy during selection but met every threshold on a fresh set, and agrees with a second auditor at $\kappa=0.635$. The extension and repeated-sampling checks use raw harness outcomes (Appendix~\ref{app:outcome-audit}).

\textbf{Scorer dependence and human disagreement.} Common-mode LLM-rater bias can propagate into the index; the ensemble makes disagreement observable but cannot remove it. Human-LLM agreement is only moderate on the disagreement-enriched sample and varies by rater.

\textbf{No causal IV claim.} The overidentification restrictions reject even in small subsamples and candidate instruments imply conflicting coefficients, so the 2SLS fits cannot identify a causal effect.

\textbf{Scope.} AuroraGPT-IT-v4 was excluded post hoc without a prespecified rule, so a like-for-like 22-model sensitivity is unavailable. The extension adds 351 prompts at bins 15 and 16 but only 14 above 16, leaving that endpoint underpowered. Generation and execution are Python-only; Java and C++ results test score transfer only. The task taxonomy, frame sensitivity, extension, human, paraphrase, language, and repeated-sampling checks were added post hoc and are not preregistered, and we do not track prompts or model families over time.

% =====================================================================
\section{Conclusion}
% =====================================================================

Generated-output cyclomatic complexity is a poor stand-in for prompt structure when failures produce short or unscorable programs. A prompt-side index avoids that timing problem and supports model-specific breakpoint estimation; the clearest downward example is Kimi K2.5 near 14.25, after construction-frame control and within the later frame. The mean-pooled result is less stable: task type shrinks its gap, the large rebound is mostly compositional, median pooling and the outcome definition move it, and model directions differ. The audit-clean extension closely matches bins 15 and 16, human calibration is moderate, paraphrase, language, and repeated-sampling checks preserve ordering and location, and the candidate instruments fail their joint restrictions, so the contribution is measurement and observational analysis, not causal identification. For benchmark designers the lesson is modest: supplement output-derived metrics with pre-generation measures, publish the rubric and rater uncertainty, show support counts, and report how composition and pooling alter the curve.

\subsection{Bootstrap and placebo settings}

The mean-pooled analysis uses 2{,}000 wild-bootstrap draws, 1{,}000 pairs-bootstrap draws for the interval, and 2{,}000 shuffled-index placebo draws. Unadjusted model-specific fits use 500 wild-bootstrap and 500 placebo draws. The task-type and construction-frame controlled pooled searches each use a 300-draw wild bootstrap. The model-specific construction-frame searches use 300 wild-bootstrap draws with seed 42, and the within-frame threshold intervals use 300 pairs-bootstrap resamples.

Figure~\ref{fig:sankey} expands the 2-by-2 diagnostic in Figure~\ref{fig:output-cc}. Zero-pass complete cases flow from Lizard complexity on generated code to the prompt composite. Highlighted flows are prompts with composite $>8$ whose failed outputs have CC $\leq10$.

\section{Outcome audit}
\label{app:outcome-audit}

\textbf{Why the outcome is audited.} A unit-test verdict can err in both directions: the supplied tests call specific function names and expect exact output formats, so valid code can fail them, while weak tests can pass defective code. The reviewed version of this paper asked \texttt{o4-mini} whether each harness verdict was correct on the merits, given the task, code, tests, and harness pass rate, and to treat function-name mismatches, script-style input and output, and formatting differences as correct; ``correct'' set the pass rate to 1.0, ``incorrect'' to 0.0, and ``uncertain'' kept the harness value. That audit covered only the 2{,}246 earlier-frame prompts (46{,}706 of 47{,}166 generations, of which 15{,}725 rose to 1.0 and 8{,}123 fell to 0.0), so the outcome definition coincided with the construction-frame indicator, and \texttt{o4-mini} is also a rubric judge. For this version, one auditor from a vendor used nowhere else in the study (not a rubric judge, an evaluated model, or the paraphraser) audited all 105{,}000 generations with the same system prompt, inputs, and verdict mapping; uncertain and unparseable verdicts keep the harness value.

\textbf{Selection protocol.} A protocol written before any auditor was scored fixed a known-answer set and a selection rule. The set draws 150 benchmark prompts, stratified across display bins, whose reference solution passes every unit test, and builds three cases from each, all executed in the benchmark harness inside a network-isolated container: the normalized reference (clean; correct), a copy with the test-called functions renamed so that the harness fails it (cosmetic; correct), and the most subtle single AST mutation that the tests detect (bug; incorrect). An auditor is eligible if at most 2\% of its responses are unparseable or failed, it judges at least 95\% of clean cases correct, and it rescues at least 90\% of cosmetic cases; among eligible auditors, the lowest wrong-rescue rate on bugs wins.

\textbf{Amendments and selection.} Four dated amendments are recorded in the repository. Before any pilot case was scored, the closing format reminder was reworded identically for all auditors after a smoke test in which one candidate misread it. Neither Azure-deployed candidate was eligible (Table~\ref{tab:auditor-pilot}), so the pool was extended to hosted models from unused vendors, with a new requirement that a selected auditor also meet the rule on a fresh, disjoint known-answer set at the production endpoint. Two further candidates failed, and MiMo-V2.6-Pro was then added. It had the highest overall accuracy and the best cosmetic rescue but judged 140 of 150 clean references correct against the required 143, so no candidate met the rule in full, and we adopted it by author decision. The clean labels are themselves noisy: 35 of the 150 references are rejected by at least one auditor in Table~\ref{tab:auditor-pilot}, some for violating an explicit task instruction that the tests do not check, and at least one other auditor also rejects 7 of the 9 references that MiMo-V2.6-Pro rejects. On the fresh set, MiMo-V2.6-Pro met every threshold. No human review of the disputed references was performed.

\section{Dataset, code, and reproducibility details}
\label{app:artifact}

\textbf{Dataset.} The public data release, linked from \codeurl{}, contains the 5{,}000 locked prompts with source identifiers and construction-frame labels, the 19{,}997 per-judge rubric score rows and ensemble aggregates, all 105{,}000 generations with Lizard output complexity and three outcome columns (raw harness, the independent audit, and the reviewed version's audit) plus the auditor's verdicts, the known-answer audit sets with every auditor's responses, the repeated-sampling subset, the human calibration grades, and the 365-prompt audit-clean extension. It is documented with a dataset card and Croissant metadata including the Responsible-AI fields. % TODO(camera-ready): reconcile this list with the final release inventory.

\textbf{Code.} The repository (\codeurl{}) contains the six-dimension rubric prompt, model metadata, and analysis scripts for the breakpoint, task-control, construction-frame, diagnostic-IV, placebo, and figure pipelines, together with locked summary outputs and the source tables for every figure. Re-running model inference additionally requires provider access; all reported analyses can be reproduced from the released data without it.

\textbf{Existing assets and licenses.} The source task pool is OpenCodeInstruct under CC BY 4.0~\cite{opencodeinst}, and the derived benchmark is released under CC BY 4.0. % TODO(camera-ready): confirm licensing of released model outputs against each provider's terms.
Generated-output cyclomatic complexity is computed with Lizard 1.21.0 under the MIT License~\cite{lizard}; diagnostic IV estimation uses \texttt{linearmodels} 7.0 under the NCSA License~\cite{linearmodels}. The code repository is released under the MIT License.

\textbf{Compute.} The main compute cost is inference: four rubric judges score 5{,}000 prompts each, and 21 evaluated models each generate one answer for every prompt. Open-weight or locally served models are run one model at a time on A100-class GPU workers; serverless/API models are run through provider batch or hosted inference endpoints. The outcome audit sends one request per generation to a hosted auditor (105{,}000 production requests, plus 450 known-answer cases per auditor per set and 5{,}250 agreement-sample requests per second auditor). Unit-test execution, Lizard scoring, and econometric analysis run on CPU workers. Exact wall times, worker memory, and total compute were not logged consistently across providers, so we do not claim a complete compute accounting.

\textbf{Execution safeguards.} Generated code is executed only inside the benchmark unit-test harness with timeouts and isolated working directories; the audit's known-answer variants run in the same harness inside a container without network access, and the auditor reads code but never executes it. The source artifact does not release a trained model or a public code-generation service.

\textbf{LLM usage.} LLMs are part of the core methodology as rubric judges, as evaluated code-generation models, and as the outcome auditor. LLM-assisted drafting and editing were also used under author supervision; all scientific claims, analysis choices, and final text remain the authors' responsibility.
